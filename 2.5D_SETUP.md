# 2.5D character setup

The game continues to simulate movement and collisions in 2D. Only the visual child is 3D.

## Player or enemy prefab hierarchy

```text
CharacterRoot
├── Rigidbody2D / Collider2D / gameplay scripts
└── Model3D
    ├── Animator
    └── skinned meshes
```

1. Keep all gameplay components, including the existing `AnimatorController`, on `CharacterRoot`.
2. Add the imported FBX/model prefab as a child named `Model3D`.
3. Add `CharacterVisual3D` to `CharacterRoot`. It can auto-detect the model, or its fields can be assigned explicitly.
4. Set the model's feet at local `(0, 0, 0)` and adjust only `Model3D` scale.
5. The model Animator Controller must contain an integer parameter named `status` using the existing values in `AnimationStatus`.
6. Keep a separate sprite in `Sprites/Enemies/<enemy name>` for the enemy HUD portrait.

`CharacterVisual3D` disables old child `SpriteRenderer` visuals when a mesh is configured. Disable `Hide Sprite Visuals` if a character intentionally mixes sprite and mesh parts.

## Animation states

| Value | State |
|---:|---|
| 0 | Idle |
| 1 | Attack |
| 2 | Move |
| 3 | Action |
| 4 | Die |
| 5 | Jump |
| 6 | Point |
| 7 | Kneel |
| 8 | Wake |
| 9 | Down |
| 10 | Hurt |
| 11 | Cry |

Transitions in the 3D Animator Controller should use `status == value`.

## Rendering

- Keep the camera orthographic for the initial conversion.
- Use lit materials on 3D models and unlit sprite materials on scenery.
- Put characters on one fixed gameplay Z plane.
- Use a directional light and a simple blob shadow beneath each model.
- Keep UI and dialogue portraits in their existing canvases.
